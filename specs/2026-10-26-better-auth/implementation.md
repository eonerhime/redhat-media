## Deviations from plan

- **Better Auth 1.7.12, not 1.7.13.** `pnpm add better-auth@1.7.13` added `minimumReleaseAgeExclude` entries to `pnpm-workspace.yaml`, because 1.7.13 (2026-10-25) was inside pnpm 12's default release-age cooldown. Rather than weaken that supply-chain control, the change was reverted and 1.7.12 (2026-10-20) pinned. Move to a newer 1.7.x through Dependabot.
- **The CLI is the `auth` package.** `@better-auth/cli` stops at 1.4; from 1.5 the CLI is published as `auth` from the better-auth repository. `npx auth@1.7.12` was used, matching the library.
- **Wrong 2FA codes use the plugin's lockout (spec D4 amended).** Better Auth 1.7's `twoFactor` plugin has a per-account `accountLockout` for codes (default 10 / 15 min). It is set to 5 / 15 min instead of hand-writing hooks on the verify paths. The sign-in hook refuses while either lock is active, so owner answer H still holds. One difference: password and code failures are counted separately (5 of each), not in one shared count.
- **D17 amended (owner answer L).** The CI browser login in the `db` job can't work: `lib/db.ts` uses `@prisma/adapter-neon`, which reaches Neon over WebSockets only, so a `next start` server in CI can't use the job's plain Postgres. The owner chose: the database tests through the real handler, CI browser checks that need no account (preview-e2e in on-mode, the `ci` job in off-mode), and the owner's own sign-in on the preview. The full browser flow stays in `cms.spec.ts`, run when admin credentials are given (locally against Neon `dev`).
- **D21 added: allowlist and strict origin.** Better Auth registers about 50 endpoints. The route now passes only the 9 that Phase 24 uses; `/two-factor/disable` and the OTP endpoints join `disabledPaths`. Better Auth checks `Origin` only when cookies are present, so the route also refuses any POST from an untrusted origin.
- **`adminClient` not added** (plan 3.1): nothing in Phase 24 calls the admin API from the browser. Phase 33 adds it.
- **The session checks live in each page, not the layout** (plan 3.2). A layout can't see the path, so it can't tell `/cms/login` (open) from `/cms` (signed in). `getStaffSession()` in each session-dependent page does the redirect.
- **`.gitignore` unchanged** (plan 4.1): its `.env*` rule already covers `.env.admin-*.local`, and the scripts check with `git check-ignore`.
- **The `ci` job keeps the CMS off** (plan 2.1 said on in CI), so it tests the off-mode 404s; preview-e2e tests on-mode.
- **Lighthouse on `/cms/login` runs in CI** (plan 6.4 planned a one-off run). The bypass secret exists only in GitHub, and the job then checks every later preview too.

## Issues and fixes

- **pnpm hangs after writing the lockfile** (as on 2026-10-20). `pnpm add` and `pnpm install` wrote `pnpm-lock.yaml` and `node_modules`, then sat idle until the timeout, and `--frozen-lockfile --offline` hung the same way. The `better-auth` entry in `package.json` was added by hand. CI's `pnpm install --frozen-lockfile` is the lockfile check.
- **Better Auth skips its origin check under test.** `skipOriginCheck` defaults to true when `isTest()` (e.g. `NODE_ENV=test`), so a cookie-bearing request from another origin passed in `auth.db.test.ts`. `createAuth` now sets `advanced.disableOriginCheck: false` and `disableCSRFCheck: false` explicitly, so tests exercise what production runs. The test then passed (403).
- **The CMS-off build failed** at first: "Error occurred prerendering page /cms … CMS_ENABLED is off". The layout's `notFound()` doesn't stop the page body, which renders beside it, and the page's session check called `getAuth()`. `getStaffSession()` now calls `notFound()` itself while the CMS is off. Found by building with the CMS off before pushing.
- **The lint ban caught the client API.** `no-restricted-properties` on `verifyBackupCode` also matched `authClient.twoFactor.verifyBackupCode`. Replaced with a `no-restricted-syntax` selector that matches only `….api.<method>`; the fixture test covers both.
- **Next's lint flags `window.location.assign`** to internal pages (`--max-warnings 0`): the forms navigate with `useRouter()` instead, and sign-out also calls `router.refresh()` to drop the client router cache.
- **`twoFactor.enable()` returns a union** (`{ method: "otp" }` or the TOTP set-up), so the set-up form narrows on `"totpURI" in data`.
- **Security review (plan 6.3), 2026-10-26.** `/security-review` over `e7b028b..559fe04` found nothing reportable. It confirmed: the 2FA step can't be skipped (the plugin deletes the password-step session for 2FA users; only the two allowlisted verify endpoints accept the challenge cookie); no self-promotion (allowlist, `input: false` fields, the `role` CHECK); the lockout can't be bypassed by case variants; the origin checks; and no secret or personal data reaches the logs. Below its bar, two notes: (1) turning 2FA on replaced only the caller's session, so another password-only session opened earlier stayed valid and counted as signed in afterwards. **Fixed:** the after-hook on a successful `verify-totp` that came with a session cookie (the set-up step) ends the user's other sessions, with a database test. (2) `deactivatedAt` isn't checked on live sessions at `/api/auth`; nothing sets it until Phase 33, whose deactivation must revoke sessions.
